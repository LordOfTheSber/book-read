# Roadmap

Документ описывает направление развития Library Tracker: что чинить в первую очередь,
как развивать функциональность и в каком порядке это выпускать.

Оценки объёма: **S** — дни, **M** — 1–2 недели, **L** — месяц и больше.

---

## Текущее состояние

| Область | Состояние |
|---|---|
| Backend | Spring Boot 3.4.4 / Java 21, 399 тестов, включая матрицу ролей по всем контроллерам |
| Frontend | React 18 + Vite + Ant Design, FSD-структура, 36 юнит-тестов и 4 сценария Playwright |
| БД | PostgreSQL + Flyway (V1–V13), индексы расставлены; тесты идут на PostgreSQL в Testcontainers |
| Инфраструктура | docker-compose, скрипт деплоя на Ubuntu, манифест k8s, CI на GitHub Actions, метрики через Actuator |

Готово функционально: CRUD произведений с фильтрами, роли
(`SUPER_ADMIN` / `ADMIN` / `EDITOR` / `USER`), JWT + серверные сессии, базовая аналитика,
мониторинг узлов и метрик, экспорт и бэкапы, обновлённый UI.

Технический фундамент (P0 и P1) закрыт: уязвимости устранены, тесты и CI на месте.
Из части II закрыты разделы 1–4: карточка произведения, прогресс и время,
мультимедийность, оценки и мнения. Дальше — ввод данных (раздел 5), без которого
остальные функции не увидят данных.

## Часть I. Технический фундамент

### P0 — блокеры продакшена ✅ закрыто

1. **IDOR при редактировании произведения** — `LibraryItemService.update()` ✅
   Метод был единственным без проверки владельца: пользователь с ролью `USER`, зная UUID, мог
   перезаписать чужую запись. Добавлена та же проверка `isOwnedBy`, что в `getById()` и `delete()`;
   в `LibraryItemServiceTest` три теста — отказ не-владельцу (воспроизводит проблему), доступ
   владельцу и доступ администратору.

2. **JWT-секрет захардкожен** — `JwtService` ✅
   Дефолт из публичного репозитория убран. Секрет читается из `SECURITY_JWT_SECRET`; в профиле
   `prod` он обязателен и приложение падает на старте без него, вне прода генерируется временный.
   Отдельно отвергаются секреты короче 32 байт и старое скомпрометированное значение.
   Переменная прокинута в `docker-compose.prod.yml`, манифест k8s (`Secret book-read-backend`)
   и оба скрипта установки — они переиспользуют секрет прошлой установки, чтобы не разлогинивать всех.

3. **Cookie `secure(false)` при HTTPS-деплое** — `SessionService.buildCookie()` ✅ (шаг 1)
   Флаг вынесен в `security.cookie.secure` (плюс `same-site`), в профиле `prod` — `true`.
   Шаг 2 — увести JWT из `localStorage` в httpOnly-куку — остаётся открытым и вынесен в P1.

4. **Нет logout и отзыва токена** ✅
   Добавлены `POST /auth/logout` (гасит серверную сессию и стирает куку, идемпотентен)
   и `POST /auth/refresh` (выдаёт новый access-токен по живой сессии, отвергает заблокированного
   пользователя). Срок жизни access-токена сокращён с 24 часов до 30 минут; фронтенд обновляет
   токен молча в перехватчике `httpClient` и разлогинивает пользователя, когда сессия мертва.

5. **Отсутствует CI** ✅
   `.github/workflows/ci.yml`: на каждый PR и push в `main`/`release/**` — `mvn test` для бэкенда,
   `npm run lint`, `npm run typecheck` и `npm run build` для фронтенда. Тайп-чек отдельным шагом,
   поскольку `npm run build` — чистый `vite build`. Попутно починен линт: он не проверял ни одного
   файла (нет TS-парсера и `--ext`), теперь работает `@typescript-eslint`.

### P1 — качество и надёжность ✅ закрыто

1. **Тесты HTTP-слоя** ✅
   `ControllerSecurityMatrixTest` перебирает 36 эндпоинтов на четырёх ролях плюс анонимный
   доступ — 181 проверка. Права были разложены по двум местам, правилам URL в `SecurityConfig`
   и `@PreAuthorize` на методах, и суммы не было видно ни в одном файле. Матрица заодно вскрыла
   мёртвые правила: конфигурация разграничивала `/api/v1/book-types/**`, тогда как контроллер
   отвечает на `/api/v1/types` (поведение не менялось — те же роли задавал `@PreAuthorize`).
   Отдельный `LibraryItemControllerTest` проверяет, что отказ по владельцу (P0-1) доезжает
   до клиента как 403, а не как 500 и не как чужие данные.

2. **JWT в httpOnly-куке** (шаг 2 из P0-3) ✅
   Access-токен больше не возвращается в теле ответа и не хранится в `localStorage`: он уходит
   кукой `ACCESS_TOKEN` с теми же `secure` и `same-site`, что и сессионная. Фильтр читает токен
   из куки, заголовок `Authorization` остался запасным путём для клиентов без хранилища кук.
   Фронтенд вместо токена держит несекретный флаг «вход выполнен». Куку браузер отправляет сам,
   поэтому от CSRF теперь защищает `SameSite=Lax`: ослаблять его до `None` нельзя, не включив
   CSRF-токены.

3. **Testcontainers вместо H2** ✅
   Тесты шли на H2 в режиме совместимости, схему создавал Hibernate, а Flyway был выключен —
   миграции не проверялись вообще. Общий `PostgresContainerTest` поднимает PostgreSQL 16 и отдаёт
   его координаты через `@DynamicPropertySource`; схему строит Flyway. Без Docker наследники
   помечаются пропущенными, поэтому в CI перед прогоном проверяется `docker version`.

4. **Тесты фронтенда** ✅
   Vitest + Testing Library: 21 проверка на слайсы Redux и на формы (`BookFormDrawer`, панель
   фильтров). Playwright: три сквозных сценария на живом стеке — регистрация, добавление книги
   с проверкой после перезагрузки, выход; сценарий регистрации отдельно убеждается, что токен
   пришёл httpOnly-кукой и не осел в `localStorage`. В CI добавлена задача e2e с сервисным
   контейнером PostgreSQL.

5. **N+1 в списке произведений** ✅
   `toResponse` читал три ленивые связи у каждой строки выдачи: страница из 20 записей давала
   до 61 запроса. Добавлен `@EntityGraph` на `findAll(Specification, Pageable)`
   и `findWithRelationsById`; связи только `*ToOne`, поэтому пагинация осталась на стороне БД.

6. **Метрики при нескольких репликах** ✅
   Подключены Actuator и `micrometer-registry-prometheus`: те же запросы считаются метрикой
   `http.server.requests` с метками `application` и `node`, где ключ узла совпадает с показанным
   на странице «Узлы». Суммирование по репликам и история переехали в Prometheus, собственные
   страницы остались интерфейсом поверх тех же счётчиков. `/actuator/health` открыт для проб
   (в манифест k8s добавлены readiness и liveness), остальное — только администраторам.

7. **Обращение к БД на каждом запросе** ✅
   Пользователь кэшируется на 30 секунд (Guava — она уже кэширует сессии в `SessionService`);
   блокировка, смена роли и правка настроек сбрасывают запись явно. Продление сессии доходит
   до БД, только когда срок сдвинулся хотя бы на минуту: прежнее условие «новый срок позже
   старого» выполнялось на каждом запросе.

8. **Секреты в открытом виде** ✅
   Пароль `library/library` убран отовсюду. Оба скрипта установки обращаются с паролем БД так же,
   как с JWT-секретом: берут из окружения, иначе из прошлой установки (`deploy/.env` или Secret
   `book-read-db`), иначе генерируют; значения по умолчанию нет ни в одном пути. `deploy/.env`
   создаётся с правами 0600 и добавлен в `.gitignore`. Локальный `docker-compose.yml` требует
   `POSTGRES_PASSWORD` и падает без него, порт БД переехал на `127.0.0.1`.

## Часть II. Функциональное развитие

### 1. Карточка произведения ✅ закрыто

`Author` и `Series` — отдельные сущности (`ManyToMany` и `ManyToOne` соответственно).
Карточка присылает не идентификаторы, а имена: незнакомое имя заводится на сервере, совпадение
ищется без учёта регистра. Правятся авторы и серии на своих страницах, там же видны счётчик
произведений и прогресс по циклу.

Добавлены `isbn`, `publishedYear`, `language`, `pageCount`, `translator`, формат экземпляра
(бумага / электронная / аудио) и расположение (шкаф, полка) — всё в свёрнутом блоке карточки,
чтобы не мешать быстрому вводу.

Обложка хранится в объектном хранилище, а не в БД: реализации две — файловая по умолчанию и
S3-совместимая, переключение через `STORAGE_TYPE`. Grid-режим `BooksPage` теперь показывает
обложки. Авторы для страницы выдачи грузятся одним запросом: в `@EntityGraph` их класть нельзя,
иначе Hibernate утаскивает пагинацию в память.

> S3-адаптер покрыт тестами с моком клиента, но на живом бакете не прогонялся.

### 2. Прогресс и время ✅ закрыто

Даты начала и завершения ведёт сама смена статуса; проставить их руками по-прежнему можно.
Перечитывание — новый проход (`ReadingLog`) со своими датами и оценкой, а не перезапись
единственного статуса: возврат к чтению прочитанного открывает следующую попытку, отложенное
продолжается тем же проходом. `ReadingSession` хранит заход с отрезком и длительностью; быстрое
«+10» на карточке и в списке — тот же заход от текущей позиции.

Шкала прогресса отделена от числа страниц издания, поэтому её хватило и на раздел 3. По дедлайну
считаются норма в день (с округлением вверх) и отставание от равномерного графика. Добавлены
статус `ON_HOLD` и выписки: цитата с номером страницы, пометка и поиск по всем выпискам
библиотеки (индекс `pg_trgm`).

### 3. Мультимедийность ✅ закрыто

`MediaKind` расширен до `BOOK, COMIC, MANGA, AUDIOBOOK, MOVIE, SERIES, ANIME, PODCAST, GAME`.
Каждый вид знает свою единицу прогресса: у манги тома, у сериала эпизоды, у подкаста и
аудиокниги минуты — это та же `ReadingSession` из раздела 2, только шкала другая. Своя единица
в карточке главнее вида. На фронтенде — выбор вида, фильтр по виду и иконка вида в списке.

### 4. Оценки и мнения ✅ закрыто

`comment` разделён на приватную `note` и публичный `review`; существующий текст миграция
переносит в заметку — публиковать чужую запись задним числом хуже, чем оставить её закрытой.
Спойлерная часть отзыва лежит отдельным полем, поэтому интерфейс прячет её под кат, не разбирая
разметку. Добавлены критерии (сюжет, язык, персонажи, финал) — общая оценка осталась
самостоятельной. При завершении прохода оценка и критерии снимаются в `ReadingLog`, так что
после перечитывания прежняя остаётся в своём проходе.

### 5. Ввод данных

Ключевой барьер: вручную библиотеку никто заполнять не станет, и без этого блока остальные
функции не увидят данных.

- **Поиск по Open Library / Google Books** — метаданные и обложка подтягиваются автоматически.
  Самая окупаемая функция во всём списке. **M**
- **Сканер ISBN камерой** — в вебе доступно через `BarcodeDetector`. **M**
- **Импорт CSV из Goodreads / LiveLib / StoryGraph.** Существующий `ImportResponse` относится
  к административному бэкапу (`DataExportService`), а не к пользовательскому импорту:
  нужен отдельный поток с превью и разрешением дубликатов. **M**
- **Массовые операции** — проставить статус или тег сразу нескольким записям. **S**
- **Детектор дублей** при добавлении: по ISBN и по нечёткому совпадению названия. **S**

### 6. Организация библиотеки

- **Теги** — свободные, в дополнение к справочнику `BookType`: тип это жанр, теги — контекст
  («на лето», «перечитать»). **M**
- **Полки и коллекции** — именованные наборы с описанием, в том числе публичные. **M**
- **Умные полки** — сохранённый фильтр как объект. `LibraryItemFilter` уже принимает 12 параметров,
  не хватает только их сохранения. **S**
- **Список желаемого** отдельно от `PLANNED`, с ценой и ссылкой. **S**
- **Полнотекстовый поиск** — сейчас `LIKE '%…%'` по двум полям (`LibraryItemService.java:171`),
  индексы не используются. Нужен `pg_trgm` и поиск по автору, тегам, цитатам. **S**

### 7. Социальный слой

- **Публичные профили и полки** (`/u/username`) — основной источник органического роста. **M**
- **Подписки и лента активности.** **M**
- **Реакции и комментарии к отзывам.** **M**
- **Совместные библиотеки** — семейная полка, книжный клуб. Текущие роли глобальные,
  здесь нужны роли внутри коллекции. **L**
- **Учёт выданных экземпляров** — кому и когда отдана книга, напоминание вернуть. **S**

### 8. Цели и вовлечение

- Челлендж года с прогрессом и отставанием от графика. **S**
- Стрики — дни подряд с чтением. **S**
- Достижения. **M**
- «Год в обзоре» — шеринговая карточка со статистикой; почти бесплатна при наличии блока 2. **M**

### 9. Уведомления

Сценарии: давно не открывал начатое; вышла новая книга автора или следующий том серии;
приближается дедлайн; пора вернуть одолженный экземпляр.
Каналы по порядку внедрения: email → веб-пуш → Telegram-бот (бот дополнительно даёт быстрый ввод). **M**

### 10. Аналитика

Текущий `BookAnalyticsResponse` — пять статичных чисел без временных рядов. Добавить:
динамику по месяцам и годам, тепловую карту активности, скорость чтения и прогноз завершения,
разбивки по авторам, языкам и десятилетиям издания, соотношение «куплено / прочитано»,
сравнение с прошлым годом. **M**

### 11. Данные пользователя

`/api/v1/exports/**` доступен только `SUPER_ADMIN` (`SecurityConfig`) и выгружает базу целиком.
Нужны пользовательский экспорт собственной библиотеки в CSV/JSON и удаление аккаунта вместе
с данными — это и доверие, и соответствие требованиям к обработке персональных данных. **S**

### 12. PWA и офлайн

Манифест, service worker и очередь отложенных изменений дают устанавливаемое приложение
без затрат на нативную разработку. **M**

### 13. Умные функции

- Рекомендации: начать с прозрачного «похожие по тегам и авторам», без ML.
- «Что читать дальше» — выбор из `PLANNED` с учётом свободного времени.
- AI-обогащение: описание без спойлеров, авто-теги по аннотации, напоминание содержания
  предыдущего тома. Ценность в подсказке, а не в генерации отзывов за пользователя.

## Часть III. Порядок выпуска

### Спринт 0 — фундамент (первым делом)

1. ✅ Исправить IDOR в `LibraryItemService.update()` и покрыть тестом.
2. ✅ Вынести JWT-секрет в окружение с fail-fast; флаг `Secure` у куки по профилю.
3. ✅ Добавить `logout` и `refresh`, сократить срок жизни access-токена.
4. ✅ Поднять GitHub Actions: тесты бэкенда, тайп-чек и линт фронтенда на каждый PR.
5. ✅ Написать MockMvc-тесты матрицы ролей по всем контроллерам.

Пункты 1–3 закрывают эксплуатируемые уязвимости, пункт 4 не даёт сломать это повторно.
Спринт закрыт вместе с P1; следующая работа — релиз 1.

### Релиз 1 — «Полноценная карточка» ✅ закрыто, кроме поиска по Open Library

Автор как сущность, ISBN / год / страницы / язык, обложки, `startedAt` и `finishedAt`,
статус `ON_HOLD` — всё готово. Остался поиск по Open Library, он же первый пункт раздела 5.

### Релиз 2 — «Трекер»

Сессии чтения и прогресс в процентах готовы (раздел 2). Осталось: цель года, аналитика по
времени, теги и умные полки, импорт из Goodreads. На этом этапе появляется удержание.

### Релиз 3 — «Люди»

Публичные профили и полки, подписки, «Год в обзоре», шеринг. На этом этапе появляется рост.

### Параллельно

Расширение `MediaKind` ✅ сделано (раздел 3): позиционирование сменилось с книжного трекера
на дневник всего просматриваемого и прочитанного.

> Социальный слой (Релиз 3) не следует выпускать раньше, чем закрыт P0: публичные профили
> поверх незакрытого IDOR превращают локальный дефект в публичный инцидент. P0 закрыт,
> но условие остаётся в силе для любых новых точек доступа к чужим данным.
