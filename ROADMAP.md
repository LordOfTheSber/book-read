# Roadmap

Документ описывает направление развития Library Tracker: что чинить в первую очередь,
как развивать функциональность и в каком порядке это выпускать.

Оценки объёма: **S** — дни, **M** — 1–2 недели, **L** — месяц и больше.

---

## Текущее состояние

| Область | Состояние |
|---|---|
| Backend | Spring Boot 3.4.4 / Java 21, ~5300 строк, 36 тестов, тестов HTTP-слоя нет |
| Frontend | React 18 + Vite + Ant Design, FSD-структура, ~7000 строк, тестов нет |
| БД | PostgreSQL + Flyway (V1–V9), индексы расставлены |
| Инфраструктура | docker-compose, скрипт деплоя на Ubuntu, манифест k8s, CI/CD отсутствует |

Готово функционально: CRUD произведений с фильтрами, роли
(`SUPER_ADMIN` / `ADMIN` / `EDITOR` / `USER`), JWT + серверные сессии, базовая аналитика,
мониторинг узлов и метрик, экспорт и бэкапы, обновлённый UI.

Проект перерос стадию прототипа: последние итерации ушли в инфраструктуру и интерфейс,
а фундамент — безопасность, тесты, CI — остался на исходном уровне. Отсюда порядок работ ниже.

## Часть I. Технический фундамент

### P0 — блокеры продакшена

1. **IDOR при редактировании произведения** — `backend/src/main/java/com/library/tracker/service/LibraryItemService.java:67`
   `update()` — единственный метод без проверки владельца; в `getById()` и `delete()` проверка
   `isOwnedBy` есть. Пользователь с ролью `USER`, зная UUID, может перезаписать чужую запись.
   Исправление точечное, обязательно с тестом, который воспроизводит проблему.

2. **JWT-секрет захардкожен** — `backend/src/main/java/com/library/tracker/security/JwtService.java:21`
   Значение по умолчанию не переопределяется ни в `application.yml`, ни в `deploy/`, то есть
   в продакшене используется секрет из публичного репозитория. Прямую подделку токена сейчас
   гасит привязка к серверной сессии в `JwtAuthenticationFilter`, но полагаться на это нельзя.
   Нужен обязательный `SECURITY_JWT_SECRET` из окружения и fail-fast при старте в профиле `prod`.

3. **Cookie `secure(false)` при HTTPS-деплое** — `backend/src/main/java/com/library/tracker/service/SessionService.java:108`
   Деплой поднимает TLS, а сессионная кука ходит без флага `Secure`. Дополнительно токен лежит
   в `localStorage` (`frontend/src/shared/api/httpClient.ts:8`) и доступен любому XSS.
   Шаг 1 — сделать `secure` конфигурируемым по профилю, шаг 2 — увести JWT в httpOnly-куку.

4. **Нет logout и отзыва токена**
   В `AuthController` только `login` и `register`. Пользователь не может завершить свою сессию,
   JWT живёт 24 часа и не отзывается. Нужны `POST /auth/logout` и `POST /auth/refresh`,
   срок жизни access-токена сократить до 15–30 минут.

5. **Отсутствует CI**
   Ни один PR не проверяется автоматически. Минимальный workflow: `mvn test`, `tsc --noEmit`,
   `npm run lint`, `npm run build`. Тайп-чек нужен отдельным шагом: `npm run build` — это чистый
   `vite build` без проверки типов.

### P1 — качество и надёжность

- **Тесты HTTP-слоя.** Сервисы покрыты, контроллеры — нет. Именно там живут ошибки авторизации
  (см. P0-1). Нужны `@WebMvcTest` / MockMvc на матрицу ролей: для каждого эндпоинта проверить,
  что `USER` не получает доступ к чужим данным, а `EDITOR` — к административным операциям.
- **Testcontainers вместо H2.** Тесты идут на H2, продакшен — PostgreSQL, поэтому миграции Flyway
  фактически не проверяются.
- **Тесты фронтенда.** Vitest + RTL на слайсы Redux и формы (`BookFormDrawer`, панель фильтров),
  далее 2–3 e2e-сценария на Playwright.
- **N+1 в списке произведений** — `LibraryItemService.java:219` (`toResponse`). На каждую строку
  выдачи подгружаются три ленивые связи (`type`, `source`, `createdBy`): страница из 20 записей
  даёт до 61 запроса. Лечится `@EntityGraph` или проекцией в DTO.
- **Метрики в памяти при нескольких репликах.** `RequestMetricsService` копит статистику
  в `ConcurrentHashMap`, а `BACKEND_REPLICAS` по умолчанию `2` — показатели зависят от того,
  в какой под попал запрос, и обнуляются при рестарте. Рекомендуется перейти на Actuator +
  Micrometer/Prometheus, оставив собственные страницы как UI поверх готовых метрик.
- **Обращение к БД на каждом запросе.** `JwtAuthenticationFilter` при любом обращении выполняет
  `validateAndRefresh` (UPDATE сессии) и загрузку пользователя. Нужен кэш пользователя
  (Caffeine, TTL 30–60 с) и обновление сессии не чаще раза в минуту.
- **Секреты в открытом виде.** Пароли БД по умолчанию `library/library` в `docker-compose.yml`
  и в манифесте k8s. Для k8s — вынести в `Secret`, для скриптов — требовать переменные окружения.

## Часть II. Функциональное развитие

### Ключевой пробел

`LibraryItem` (`backend/src/main/java/com/library/tracker/domain/LibraryItem.java`) содержит
`title`, `altTitle`, `type`, `source`, `comment`, `rating`, `favorite`, `status` — и всё.
Нет автора, года, ISBN, обложки, числа страниц, языка, серии, дат начала и завершения.

Отсутствие автора блокирует значительную часть функций ниже: группировку, рекомендации, импорт
из внешних каталогов, поиск других произведений того же автора, содержательную аналитику.
Кроме того, `MediaKind` — enum с единственным значением `BOOK`: мультимедийность заложена
в схему, но не раскрыта.

### 1. Карточка произведения

| Фича | Описание | Объём |
|---|---|---|
| Автор | Отдельная сущность `Author` + `ManyToMany`, а не строковое поле — иначе не работают страница автора и фильтрация | M |
| Серия / цикл | `Series` + `orderInSeries`: прогресс по циклу, «следующая в серии» | M |
| Издательские метаданные | `isbn`, `publishedYear`, `language`, `pageCount`, `translator` | S |
| Обложка | Grid-режим в `BooksPage` сейчас показывает карточки без изображений. Хранить в S3-совместимом хранилище, не в БД, как сделано с аватарами | M |
| Формат экземпляра | Бумага / электронная / аудио — влияет на единицу прогресса (страницы или минуты) | S |
| Расположение | Для бумажных экземпляров: шкаф, полка | S |

### 2. Прогресс и время

Сейчас статус переключается мгновенно и бесследно: нельзя ответить, когда произведение
завершено и сколько времени заняло.

- **Даты `startedAt` / `finishedAt`** — минимальное изменение, разблокирует временную аналитику. **S**
- **Сессии чтения** (`ReadingSession`: дата, страницы с–по, длительность) — история и темп. **M**
- **Статус `ON_HOLD`** — в `ReadingStatus` есть `DROPPED`, но нет «отложено»; это разные состояния. **S**
- **Перечитывания** — `ReadingLog` с несколькими проходами вместо единственного статуса. **M**
- **Прогресс в списке** — прогресс-бар на карточке и быстрое обновление («+10 страниц»). **S**
- **Дедлайны и прогноз** — «дочитать к дате», расчёт нормы в день, подсветка отставания. **M**
- **Закладки и цитаты** — выписки с номером страницы, поиск по ним. **M**

### 3. Мультимедийность

Расширить `MediaKind` до `BOOK, COMIC, MANGA, AUDIOBOOK, MOVIE, SERIES, ANIME, PODCAST, GAME`.
Технически — enum, миграция и иконки; продуктово — переход от нишевого книжного трекера
к единому дневнику потребления контента. Для сериалов и манги нужен учёт по эпизодам и томам
(та же `ReadingSession`, другая единица измерения). **M → L**

### 4. Оценки и мнения

- Разделить приватную заметку и публичный отзыв — сейчас это одно поле `comment`. **S**
- Многокритериальная оценка (сюжет, язык, персонажи, финал); `rating` уже `BigDecimal(3,1)`. **S**
- Спойлер-кат в отзывах. **S**
- История оценки при перечитывании. **S**

### 5. Ввод данных

Ключевой барьер: вручную библиотеку никто заполнять не станет, и без этого блока остальные
функции не увидят данных.

- **Поиск по Open Library / Google Books** — метаданные и обложка подтягиваются автоматически.
  Самая окупаемая функция во всём списке. **M**
- **Сканер ISBN камерой** — в вебе доступно через `BarcodeDetector`. **M**
- **Импорт CSV из Goodreads / LiveLib / StoryGraph.** Существующий `ImportResponse` относится
  к административному бэкапу (`DataExportService`), а не к пользовательскому импорту:
  нужен отдельный поток с превью и разрешением дубликатов. **M**
- **Массовые операции** — проставить статус или тег сразу нескольким записям. **S**
- **Детектор дублей** при добавлении: по ISBN и по нечёткому совпадению названия. **S**

### 6. Организация библиотеки

- **Теги** — свободные, в дополнение к справочнику `BookType`: тип это жанр, теги — контекст
  («на лето», «перечитать»). **M**
- **Полки и коллекции** — именованные наборы с описанием, в том числе публичные. **M**
- **Умные полки** — сохранённый фильтр как объект. `LibraryItemFilter` уже принимает 12 параметров,
  не хватает только их сохранения. **S**
- **Список желаемого** отдельно от `PLANNED`, с ценой и ссылкой. **S**
- **Полнотекстовый поиск** — сейчас `LIKE '%…%'` по двум полям (`LibraryItemService.java:171`),
  индексы не используются. Нужен `pg_trgm` и поиск по автору, тегам, цитатам. **S**

### 7. Социальный слой

- **Публичные профили и полки** (`/u/username`) — основной источник органического роста. **M**
- **Подписки и лента активности.** **M**
- **Реакции и комментарии к отзывам.** **M**
- **Совместные библиотеки** — семейная полка, книжный клуб. Текущие роли глобальные,
  здесь нужны роли внутри коллекции. **L**
- **Учёт выданных экземпляров** — кому и когда отдана книга, напоминание вернуть. **S**

### 8. Цели и вовлечение

- Челлендж года с прогрессом и отставанием от графика. **S**
- Стрики — дни подряд с чтением. **S**
- Достижения. **M**
- «Год в обзоре» — шеринговая карточка со статистикой; почти бесплатна при наличии блока 2. **M**

### 9. Уведомления

Сценарии: давно не открывал начатое; вышла новая книга автора или следующий том серии;
приближается дедлайн; пора вернуть одолженный экземпляр.
Каналы по порядку внедрения: email → веб-пуш → Telegram-бот (бот дополнительно даёт быстрый ввод). **M**

### 10. Аналитика

Текущий `BookAnalyticsResponse` — пять статичных чисел без временных рядов. Добавить:
динамику по месяцам и годам, тепловую карту активности, скорость чтения и прогноз завершения,
разбивки по авторам, языкам и десятилетиям издания, соотношение «куплено / прочитано»,
сравнение с прошлым годом. **M**

### 11. Данные пользователя

`/api/v1/exports/**` доступен только `SUPER_ADMIN` (`SecurityConfig`) и выгружает базу целиком.
Нужны пользовательский экспорт собственной библиотеки в CSV/JSON и удаление аккаунта вместе
с данными — это и доверие, и соответствие требованиям к обработке персональных данных. **S**

### 12. PWA и офлайн

Манифест, service worker и очередь отложенных изменений дают устанавливаемое приложение
без затрат на нативную разработку. **M**

### 13. Умные функции

- Рекомендации: начать с прозрачного «похожие по тегам и авторам», без ML.
- «Что читать дальше» — выбор из `PLANNED` с учётом свободного времени.
- AI-обогащение: описание без спойлеров, авто-теги по аннотации, напоминание содержания
  предыдущего тома. Ценность в подсказке, а не в генерации отзывов за пользователя.

## Часть III. Порядок выпуска

### Спринт 0 — фундамент (первым делом)

1. Исправить IDOR в `LibraryItemService.update()` и покрыть тестом.
2. Вынести JWT-секрет в окружение с fail-fast; флаг `Secure` у куки по профилю.
3. Добавить `logout` и `refresh`, сократить срок жизни access-токена.
4. Поднять GitHub Actions: тесты бэкенда, тайп-чек и линт фронтенда на каждый PR.
5. Написать MockMvc-тесты матрицы ролей по всем контроллерам.

Пункты 1–3 занимают два-три дня и закрывают эксплуатируемые уязвимости, пункты 4–5 не дают
сломать это повторно.

### Релиз 1 — «Полноценная карточка»

Автор как сущность, ISBN / год / страницы / язык, обложки, `startedAt` и `finishedAt`,
статус `ON_HOLD`, поиск по Open Library. Без этого блока остальное строится на пустой карточке.

### Релиз 2 — «Трекер»

Сессии чтения, прогресс в процентах, цель года, аналитика по времени, теги и умные полки,
импорт из Goodreads. На этом этапе появляется удержание.

### Релиз 3 — «Люди»

Публичные профили и полки, подписки, «Год в обзоре», шеринг. На этом этапе появляется рост.

### Параллельно

Расширение `MediaKind` можно делать в любой момент: технически дёшево, а позиционирование
меняет существенно — от книжного трекера к дневнику всего просматриваемого и прочитанного.

> Социальный слой (Релиз 3) не следует выпускать раньше, чем закрыт P0: публичные профили
> поверх незакрытого IDOR превращают локальный дефект в публичный инцидент.
